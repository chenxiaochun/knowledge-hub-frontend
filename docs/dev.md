# 开发规范

## 文件体量

- **单个源文件不得超过 450 行**（含空行与注释；`.ts` / `.tsx` / `.scss` 等均适用）。
- 接近或超过上限时，必须在合入前按职责拆分，而不是继续堆叠逻辑。
- 自动生成文件（如 `ts-gear` 产出）可例外，但不要在生成文件中手写业务逻辑。

## 拆分与复用

拆分要以**真实业务边界**为准，避免为凑行数而机械切文件。

优先按职责拆分，例如：

| 类型 | 建议放置 |
| --- | --- |
| 页面编排 / 路由入口 | `pages/<Feature>/index.tsx` |
| 可复用 UI 片段 | `pages/<Feature>/components/` 或 `components/` |
| 请求与数据转换 | `hooks/`、`utils/` 或页面旁 `*.ts` |
| 常量、枚举、纯类型 | `constants/`、`types` 或同目录 `types.ts` |
| 表格列、表单 schema 等配置 | 独立 `columns.tsx` / `form.tsx` 等 |

复用原则：

- **相同逻辑出现两处及以上**时，抽成共享函数、hook 或组件，而不是复制粘贴。
- 抽公共代码前先确认抽象稳定；过早抽象、为复用而复用同样不可取。
- 页面私有、短期不会复用的逻辑，优先留在当前 feature 目录内，不要急着升到全局 `components/`。
- 拆分后每个文件应职责单一、命名能直接反映用途，避免 `helpers2.ts`、`utilsNew.ts` 这类含糊命名。

## 自检

提交前确认：

1. 改动涉及的源文件均 ≤ 450 行。
2. 新增拆分对应清晰职责，而不是随意均分行数。
3. 可复用逻辑已落到合适位置，页面文件主要负责组合与交互编排。
